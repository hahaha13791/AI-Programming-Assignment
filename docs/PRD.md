# Listen to the world (가제) — 요구사항 정의서 (PRD)

## 1. 프로젝트 개요

- 프로젝트 이름: Listen to the world (가제)
- 한 줄 소개: 청음 연습(멜로디·화성·리듬 받아적기)을 서포트하고, 내 악보로도 연습할 수 있는 사이트
- 만드는 사람: 양인권 / 튜너
- 완성 목표일: 2026-10-04(일) — 1차(멜로디 모드) 완료
- 확장 1(화성 모드): 2026-10-04 완료
- 확장 2(7화음): 2026-10-05 완료
- 확장 3(리듬 모드): 2026-10-06 완료
- 확장 4(내 악보): 2026-10-08 완료
- 확장 5(원곡 악보 형식): 2026-10-31 완료
- 확장 6(MusicXML 불러오기): 2026-10-31 완료
- 확장 7(편집기 넓히기): 2026-10-31 완료

- 확장 10(악보 자동 계이름 표시): 진행 중

## 2. 왜 만드나요? (목적)

계이름을 귀찮게 적는 일을 없애고, 청음 연습을 서포트한다.

청음(聽音)은 본래 들리는 소리·리듬·화성 등을 파악해 악보에 옮기는 연습/시험 과정 전반을 뜻한다. 절대음감 테스트(소리 하나만 듣고 음을 맞히는 것)가 아니라, **기준음(조성)을 잡고 그 안에서 상대적인 계이름을 받아 적는 훈련**이 청음의 본질이다.

두 목적 중 **"청음 연습 서포트"**에 집중한다. 청음의 3요소(음높이·리듬·화성) 중 1차 버전은 **멜로디(음높이) 받아적기**를 다뤘고, 확장 1에서 **화성(화음 구성음) 받아적기**를 더했고, 확장 2에서 화성 모드에 **7화음**을 더했다. 확장 3에서 마지막 요소인 **리듬 받아적기**를 더했다. "계이름 적는 일 없애기"(악보 자동 계이름 표시)는 확장 10에서 내 악보의 [보기] 화면으로 더한다 (4-K).

확장 4부터는 **차별점**을 더한다. 정해진 문제만 푸는 다른 청음 앱과 달리, 사용자가 **자기가 연습하고 싶은 곡을 악보로 직접 입력**하고 그 악보를 구간별 청음 문제로 연습할 수 있게 한다. 입력 방식은 직접 입력(확장 4) → MusicXML 불러오기(확장 6) → 악보 인식(OCR)·곡 검색 순서로 넓혀 간다 (11번 항목 참고).

## 3. 누가 사용하나요? (사용자)

- 주 사용자: 음악(특히 청음) 연습을 하는 사람 — 음악 입시생, 음대생, 취미 음악인 등 계이름 받아적기 훈련이 필요한 사람
- 사용 환경: 브라우저에서 바로 여는 정적 웹앱 (PC/모바일 모두 고려, 별도 설치·로그인 없이 사용)
- 사용자에 대해 알아야 할 점: 이미 계이름(도레미파솔라시) 개념과 오선 악보를 알고 있는 사람을 전제로 한다. 절대음감이 아니라 상대음감 방식의 훈련을 원한다.

## 3-1. 대표 사용자 페르소나

- 이름/나이: 김서연 / 18세 (가상 인물)
- 상황: 음대 입시를 준비하는 고3. 레슨 없는 날 집에서 혼자 청음을 연습하고 싶지만, 문제를 들려주고 채점해 줄 사람이 없다.
- 바라는 것: 버튼 몇 번으로 문제를 듣고, 오선에 받아 적고, 바로 어디가 틀렸는지 확인하는 것
- 불편해하는 것: 설치·가입 절차, 틀린 음과 정답을 알려주지 않는 채점, 한 음 틀렸다고 전부 다시 입력해야 하는 입력 방식

## 4. 꼭 있어야 하는 기능 (핵심 기능)

### 4-0. 공통

1. 사용자는 화면 맨 위의 탭에서 **[멜로디 | 화성 | 리듬 | 내 악보]** 모드를 고를 수 있다. 모드를 바꾸면 그 모드의 새 문제가 나온다.
2. 모든 모드는 같은 화면 구성(난이도 → 듣기 → 받아 적기 → 결과)과 같은 조작(지우기 버튼, 단계별 안내문)을 쓴다. 멜로디·화성 모드는 오선을 눌러 입력하고(♯/♭ 토글, 미리보기 음표), 리듬 모드는 음표 버튼으로 입력한다 (4-D). 내 악보 모드는 "난이도" 대신 "악보" 패널을 쓰고, 받아 적기는 멜로디 모드와 같다 (4-E). 확장 6부터 [새 악보]는 페이지 안의 작은 창을 띄워 [직접 만들기 | 파일 불러오기]를 고르게 한다 (4-G).
3. 모드를 바꿔도 "받아 적기" 영역의 위치는 움직이지 않는다. 확장 5부터 "악보" 패널(한 줄 악보 띠 포함)과 "난이도" 패널의 높이를 같게 맞춘다.
4. 확장 8부터 모든 모드의 패널 제목 줄에 ⚙ 설정이 있고, 거기서 소리 낼 악기를 고른다 (4-I).
5. 확장 9부터 리듬 모드는 화성 모드의 [3화음 | 7화음]처럼 난이도 패널 제목 줄에서 **[기본 | 심화]**를 고르고, 각각 쉬움/중간/어려움이 있다 (4-J).

### 4-A. 멜로디 모드 (1차 완료)

1. 사용자는 기준음(도)을 먼저 듣고, 이어서 짧은 멜로디(3~8음)를 들을 수 있다.
2. 사용자는 멜로디를 필요한 만큼 다시 들을 수 있다("다시 듣기").
3. 사용자는 간이 오선지(높은음자리표)를 클릭해서 들은 멜로디의 음높이를 순서대로 입력할 수 있다. 반음(#, ♭)도 입력할 수 있다. (리듬은 다루지 않음, 음높이만)
   - 입력 편의: 도(C4) 자리에 회색 덧줄 가이드를 항상 표시해, 오선 아래의 도를 어디에 찍는지 알 수 있게 한다.
   - 입력 편의: 마우스를 오선 위에 올리면, 클릭 시 입력될 음이 다음 입력 자리에 옅은 색으로 미리 보인다 (♯/♭ 토글이 켜져 있으면 임시표도 함께). 마우스가 없는 터치 환경에서는 미리보기가 나타나지 않는다.
4. 사용자는 이번 멜로디가 몇 음인지 빈칸으로 미리 볼 수 있다.
5. 사용자는 마지막으로 입력한 음 하나를 지우거나, 입력 전체를 지울 수 있다.
6. 사용자는 입력을 제출하면 음별 정답/오답과 함께 정답 멜로디를 확인할 수 있다.
7. 사용자는 난이도(쉬움/중간/어려움)를 선택하고, "다음 문제"로 계속 연습할 수 있다.

#### 진행 흐름
난이도 선택 → 기준음(도) 재생 → 멜로디(3~8음) 재생 → 사용자 입력(간이 오선 클릭, 음 개수만큼) → 제출 → 음별 채점 + 정답 공개 → 다음 문제

오선지 위 안내 문구는 단계마다 바뀌어 지금 무엇을 하면 되는지 알려준다 (듣기 전 / 듣는 중 / 입력 / 제출 후). 안내 문구 자리는 항상 같은 높이를 유지해, 문구가 바뀌어도 오선지 위치가 움직이지 않는다.

#### 멜로디 생성 방식
미리 준비된 패턴 세트 + 난이도 단계. 모든 패턴은 다장조, 음역은 도(C4)~높은 도(C5).
- 쉬움: 3~4음, 순차 진행 위주
- 중간: 5~6음, 약간의 도약 포함
- 어려움: 7~8음, 도약·반음 포함

#### 채점 규칙
- 음별로 채점한다 (부분 점수).
- 이명동음은 같은 답으로 인정한다 (예: 도# = 레♭).
- 제출 버튼은 입력한 음 개수가 멜로디 음 개수와 같을 때만 누를 수 있다.

### 4-B. 화성 모드 (확장 1)

1. 사용자는 기준음(도)을 먼저 듣고, 이어서 화음 하나(구성음이 동시에 울림)를 들을 수 있다 ("문제 듣기"). 화음은 3화음(구성음 3개) 또는 7화음(구성음 4개)이다 (4-C 참고).
2. 사용자는 화음을 필요한 만큼 다시 들을 수 있다 ("다시 듣기": 동시에, "펼쳐 듣기": 아래 음부터 하나씩 차례로).
3. 사용자는 오선의 한 자리(세로 한 줄)에 들은 구성음을 쌓아서 입력할 수 있다. 반음(#, ♭)도 입력할 수 있다.
   - 같은 줄/칸을 다시 누르면 그 자리의 음이 지워진다.
   - 마지막 음 지우기 / 전체 지우기, 도(C4) 가이드 선, 마우스 미리보기 음표는 멜로디 모드와 같다.
4. 사용자는 구성음이 몇 개인지(3화음 3개, 7화음 4개) 빈칸으로 미리 볼 수 있다. 빈칸의 계이름은 아래 음부터 위 음 순서로 채워진다.
5. 사용자는 입력을 제출하면 다음을 확인할 수 있다.
   - 내가 찍은 구성음별 정답/오답
   - 빠뜨린 정답 음
   - 정답 화음의 오선과 이름 (예: "레 장3화음 · 레 파# 라", 자리바꿈이면 "도 장3화음 첫째 자리바꿈 · 미 솔 높은 도")
6. 사용자는 난이도(쉬움/중간/어려움)를 선택하고, "다음 문제"로 계속 연습할 수 있다.

#### 진행 흐름
화음 종류(3화음/7화음)·난이도 선택 → 기준음(도) 재생 → 화음 재생 → 사용자 입력(한 자리에 구성음 쌓기, 3개 또는 4개) → 제출 → 구성음별 채점 + 정답 화음과 이름 공개 → 다음 문제

#### 화음 문제 구성
미리 준비된 화음 세트 + 난이도 단계. 기준음은 다장조의 도, 음역은 도(C4)~솔(G5). 청음 교육의 보편적인 순서(3화음 종류 → 자리바꿈 → 7화음 → 화성 진행) 중 앞의 두 단계는 3화음 난이도로, 세 번째 단계는 7화음 난이도(4-C)로 다룬다.

3화음:
- 쉬움: 장·단 3화음, 기본 위치
- 중간: 장·단·감·증 3화음, 기본 위치
- 어려움: 장·단·감·증 3화음 + 자리바꿈(첫째·둘째)

감·증 3화음이나 다장조 밖의 근음을 쓰는 화음에는 반음(#, ♭)이 섞인다.

#### 채점 규칙
- 입력한 순서와 관계없이, 구성음을 음높이로 비교한다.
- 옥타브까지 같아야 정답이다 (같은 계이름이라도 다른 옥타브면 오답).
- 이명동음은 같은 답으로 인정한다.
- 제출 버튼은 입력한 음 개수가 구성음 개수(3화음 3개, 7화음 4개)와 같을 때만 누를 수 있다.

### 4-C. 7화음 (확장 2)

화성 모드 안에서 [3화음 | 7화음]을 고르는 방식으로 넣는다. 새 모드 탭은 만들지 않는다. 입력·재생·채점·결과 화면은 4-B를 그대로 쓰고, 구성음만 4개로 늘어난다.

1. 사용자는 화성 모드에서 화음 종류 [3화음 | 7화음]을 고를 수 있다. 고르면 그 종류의 새 문제가 나온다. 이 선택은 화성 모드에서만 보인다.
   - 위치: "난이도" 제목과 같은 줄 오른쪽. 따로 한 줄을 차지하지 않아, 모드 탭이나 화음 종류를 바꿔도 오선지 위치가 움직이지 않는다.
   - 3화음과 7화음은 각각 자기 쉬움/중간/어려움을 가진다. 고른 난이도는 화음 종류를 바꿔도 유지된다.
2. 사용자는 7화음(구성음 4개)을 듣고, 오선의 한 자리에 4개를 쌓아 입력할 수 있다. 빈칸은 4개다.
3. 사용자는 제출하면 4-B-5와 같은 결과(구성음별 정답/오답, 빠뜨린 음, 정답 화음의 오선과 이름)를 확인할 수 있다.
   - 이름 예: "솔 속7화음 · 솔 시 높은 레 높은 파", 자리바꿈이면 "솔 속7화음 셋째 자리바꿈 · 파 솔 시 높은 레"

#### 7화음 문제 구성
미리 준비된 화음 세트 + 난이도 단계. 기준음·음역(C4~G5)·채점 규칙은 3화음과 같다.
- 쉬움: 속7·장7화음, 기본 위치
- 중간: 속7·장7·단7·반감7·감7화음, 기본 위치
- 어려움: 다섯 종류 + 자리바꿈(첫째·둘째·셋째)

종류별 음정 구조(아래부터 반음 수): 속7 4+3+3 / 장7 4+3+4 / 단7 3+4+3 / 반감7 3+3+4 / 감7 3+3+3

겹올림표·겹내림표(𝄪, 𝄫)는 입력할 수 없으므로, 구성음을 홑임시표만으로 적을 수 있는 화음만 출제한다.

### 4-D. 리듬 모드 (확장 3)

리듬 모드는 음높이를 다루지 않는다. 모든 소리는 한 가지 높이이고, 음표·쉼표의 길이와 박자만 받아 적는다. 쉬움·중간은 박자표가 주어지고, 어려움은 박자표도 직접 고른다.

> 확장 9부터 이 절은 리듬 [기본 | 심화]의 **기본**이다. 문제·입력·흐름은 그대로이고, 보표 그림(한 줄 보표 통일)과 채점 기준(소리 기준)은 4-J를 따른다.

1. 사용자는 카운트인을 듣고, 이어서 리듬을 들을 수 있다 ("문제 듣기"). 필요한 만큼 다시 들을 수 있다 ("다시 듣기", 카운트인 포함).
   - 쉬움·중간 카운트인: 박자표에 맞춘 1마디, 첫 박은 높은 소리
   - 어려움 카운트인: 박자와 상관없이 강세 없는 4번 (빠르기만 알려 준다)
   - 리듬은 음표 길이만큼 이어서 소리 낸다 (길이의 약 90%). 그래야 2분음표와 "4분음표 + 4분쉼표"를 귀로 구분할 수 있다.
   - 각 마디 첫 박은 조금 세게 울려, 박자를 귀로 판단할 수 있게 한다.
   - 휴대폰 폭에서 듣기 버튼은 2개지만, 숨긴 버튼 자리를 빈칸으로 남겨 듣기 영역 높이를 다른 모드와 같게 한다 (4-0-3).
2. 사용자는 음표 버튼을 눌러 들은 리듬을 순서대로 입력할 수 있다. 버튼은 온음표·점2분음표·2분음표·점4분음표·4분음표·8분음표·4분쉼표이고, 난이도에 따라 쓰는 버튼만 보인다.
   - 버튼은 음표 그림 아래에 작은 글자("4분" 등)를 단다.
   - 8분음표는 한 번에 하나씩 입력한다.
   - 마디는 자동으로 나뉜다. 지금 마디의 남은 박에 들어가지 않는 버튼은 누를 수 없다 (붙임줄 없음).
   - 마지막 음 지우기 / 전체 지우기는 다른 모드와 같다. 마우스 미리보기는 없다.
   - 어려움: ♯/♭ 자리에 박자표 버튼 [2/4 | 3/4 | 4/4]가 있다. 박자표를 고르기 전에는 음표 버튼을 누를 수 없고, 입력 중에 박자표를 바꾸면 입력이 지워진다.
3. 사용자는 리듬 보표(한 줄 보표, 박자표, 마디선)에서 입력한 리듬을 본다.
   - 쉬움·중간: 박자표와 문제의 마디 수만큼 빈 마디가 미리 보인다 (다른 모드의 빈칸 역할).
   - 어려움: 박자표 없는 빈 마디 하나로 시작한다. 박자표를 고르면 보표에 박자표가 그려지고, 마디가 차면 다음 빈 마디가 추가된다 (최대 4마디).
   - 8분음표는 한 박 안에서 둘씩 빔으로 묶고, 혼자인 8분음표는 꼬리를 단다.
   - 휴대폰 폭에서 3마디 이상은 2마디씩 두 줄로 보여 준다. 어려움은 처음부터 두 줄 높이를 잡아, 마디가 늘어도 아래 영역이 움직이지 않는다.
   - 보표 아래 한 줄(다른 모드의 계이름 미리보기 자리)에 진행 상황을 보여 준다 (예: "3마디 · 남은 박 1").
4. 사용자는 입력을 제출하면 다음을 확인할 수 있다.
   - 마디별 정답/오답 (예: "4마디 중 3마디 정답")
   - 어려움: 박자표 정답/오답 (예: "박자표 오답 (정답 3/4)")
   - 정답 리듬 보표
5. 사용자는 난이도(쉬움/중간/어려움)를 선택하고, "다음 문제"로 계속 연습할 수 있다.

#### 진행 흐름
- 쉬움·중간: 난이도 선택 → 카운트인(1마디) → 리듬 재생 → 사용자 입력(음표 버튼, 마디 수만큼) → 제출 → 마디별 채점 + 정답 리듬 공개 → 다음 문제
- 어려움: 난이도 선택 → 카운트인(강세 없는 4번) → 리듬 재생 → 박자표 고르기 → 사용자 입력(음표 버튼, 마디가 차면 다음 마디 추가) → 제출 → 박자표·마디별 채점 + 정답 리듬 공개 → 다음 문제

#### 리듬 문제 구성
미리 준비된 리듬 세트 + 난이도 단계. 빠르기는 ♩= 80 고정.
- 쉬움: 2마디, 2/4·4/4, 온음표·2분음표·4분음표
- 중간: 2마디, 2/4·3/4·4/4, + 8분음표(한 박에 둘), 점2분음표, 4분쉼표
- 어려움: 3~4마디 섞어서, 2/4·3/4·4/4, + 점4분음표 + 8분음표. 마디 수로 박자를 거꾸로 계산하지 못하도록, 난이도 설명에 마디 수를 적지 않는다.

#### 채점 규칙
- 마디별로 채점한다 (부분 점수). 마디 안 음표·쉼표의 길이와 순서가 정답과 모두 같아야 그 마디가 정답이다.
- 쉬움·중간: 제출 버튼은 모든 마디가 박을 다 채웠을 때만 누를 수 있다.
- 어려움
  - 제출 버튼은 1마디 이상 입력했고 마지막 마디가 박을 다 채웠을 때 누를 수 있다 (새로 추가된 빈 마디는 무시).
  - 박자표가 틀리면 모든 마디를 오답으로 한다 (박자표가 다르면 마디선·강박 위치가 달라져 받아 적은 악보로서 틀린 답이므로).
  - 점수는 정답 마디 수 N을 기준으로 "N마디 중 M마디 정답"이다. 입력이 모자라면 빠진 마디는 오답이고, 넘치는 마디는 오답 색으로 표시한다.

### 4-E. 내 악보 (확장 4)

사용자가 만든 악보를 구간으로 나눠, 멜로디 모드처럼 **음높이를 받아 적는** 문제로 연습한다. 악보 범위는 지금 앱의 틀 안으로 한다: 단선율, 다장조, 높은음자리표, 음역 도(C4)~솔(G5), 박자 2/4·3/4·4/4, 음표는 리듬 모드의 7종(온·점2분·2분·점4분·4분·8분음표, 4분쉼표), 최대 12마디. 못갖춘마디는 지원하지 않는다 (앞을 4분쉼표로 채워 적는다).

1. 사용자는 "악보" 패널에서 저장된 악보 중 하나를 고를 수 있다.
   - 악보는 브라우저(localStorage)에 저장되어, 같은 기기·브라우저에서 새로고침하거나 다시 열어도 남아 있다. 저장할 수 없는 환경이면 그 사실을 안내하고, 이번 방문 동안만(메모리에서) 동작한다.
     - 저장 키는 앱 접두어와 버전을 붙인다 (예: `ltw.scores.v1`). file://로 연 로컬 페이지들은 브라우저에 따라 저장소를 함께 쓰므로 다른 페이지와 겹치지 않게 한다.
     - 불러올 때 악보마다 검증한다 (음 위치 C4~G5, 임시표 ♯/♭/없음, 길이 7종, 마디 경계를 넘는 음 없음, 12마디 이하). 깨진 악보만 버리고 나머지는 남긴다.
     - 저장에 실패하면(용량 초과·접근 거부) 안내하고 메모리에서 계속 동작한다.
     - 안내 문구는 패널 높이를 바꾸지 않는 고정된 자리에 보인다.
   - 처음에는 예시 악보 1개("반짝반짝 작은 별", 공유저작물, 4/4 12마디)가 들어 있다. 저장소에 악보 목록이 아예 없을 때만 넣고, 사용자가 모두 지워 빈 목록이 되면 다시 넣지 않는다.
   - 패널에는 [새 악보] [편집] 버튼과, 고른 악보의 구간 칩("1~2마디", "3~4마디" …)이 있다.
   - "악보" 패널은 다른 모드의 "난이도" 패널과 높이가 같아, 모드를 바꿔도 받아 적기 영역이 움직이지 않는다 (4-0-3).
2. 사용자는 편집 화면에서 악보를 만들거나 고칠 수 있다.
   - 편집 화면은 "악보" 패널 아래의 듣기·받아 적기·결과 자리를 대신한다. 받아 적기 영역 위치 고정(4-0-3)은 연습 화면에만 적용한다. 편집 화면을 열면 재생 중인 소리를 멈춘다.
   - 편집 중에 모드 탭을 바꾸면 [취소]와 같이 저장하지 않은 입력을 버린다 (확인창 없음).
   - 제목과 박자표 [2/4 | 3/4 | 4/4]를 정한다. 제목은 30자까지이고, 공백만 있으면 제목이 없는 것으로 본다. 같은 제목의 악보도 만들 수 있다 (악보는 내부 id로 구분) — 확장 8 진행 중 바꿈: 편집기에서는 다른 악보와 같은 제목으로 저장하지 않는다(4-H-1). 박자표는 음표가 없을 때만 바꿀 수 있다.
   - 길이 버튼(리듬 모드의 음표 그림 버튼)으로 길이를 고른 뒤, 오선 입력판(C4~G5, ♯/♭ 토글, 미리보기 음표)의 줄/칸을 누르면 그 높이·길이의 음이 악보 끝에 붙는다. 4분쉼표 버튼은 누르면 바로 쉼표가 붙는다.
   - 음마다 실제 음높이로 저장한다. 실제 악보에서는 임시표가 그 마디 끝까지 이어지므로(예: 파# 솔 파의 둘째 파도 파#), 편집 화면에 "같은 마디라도 올리거나 내린 음은 ♯/♭을 켜고 찍으세요"를 안내한다. ♯/♭ 토글은 끌 때까지 켜져 있다.
   - 못갖춘마디로 시작하는 곡은 앞을 4분쉼표로 채워 적도록 안내한다.
   - 마디는 자동으로 나뉜다. 지금 마디의 남은 박에 들어가지 않는 길이 버튼은 누를 수 없다 (붙임줄 없음). 12마디가 차면 더 입력할 수 없다.
   - 입력한 악보는 아래 **악보 보기**(오선 위에 음높이와 길이: 기둥·꼬리·빔·점·쉼표·임시표)로 바로 보인다. 넓은 화면은 4마디씩, 휴대폰 폭에서는 2마디씩 여러 줄로 보여 준다 (임시표가 많아 한 줄에 다 들어가지 않으면 그 줄은 더 적게).
     - 임시표는 표준 표기 규칙으로 그린다: 마디 안에서 음높이가 처음 바뀌는 음에만 ♯/♭을 붙이고, 같은 마디에서 원래 음으로 돌아가면 제자리표(♮)를 붙인다.
     - 기둥은 가운데 줄(시) 이상이면 아래로, 아래면 위로 그린다. 빔으로 묶인 두 음은 가운데 줄에서 더 먼 음을 기준으로 기둥 방향을 맞춘다.
     - 줄 위에 있는 음의 점은 위 칸에 찍는다.
   - 마지막 음 지우기 / 전체 지우기 / [저장] [취소] [삭제]. 저장은 제목이 있고, 1마디 이상이며, 마지막 마디가 박을 다 채웠을 때만 된다. 삭제는 브라우저 확인창 없이, 버튼을 한 번 더 눌러 확정한다 (다른 버튼을 누르거나 3초가 지나면 확인 상태가 풀린다).
3. 악보는 앞에서부터 **2마디씩** 구간으로 나뉜다. 2마디 안의 음(쉼표 제외)이 8개를 넘으면 그 구간은 1마디로 한다 (한 마디에는 음이 최대 8개라 항상 8개 이하). 음이 하나도 없는 구간(쉼표만)은 건너뛴다.
   - 구간 칩은 최대 12개다. 칩이 한 줄에 다 들어가지 않으면 가로로 스크롤해, 패널 높이는 변하지 않는다.
   - 고른 악보를 고쳐 저장하면 구간을 다시 나누고 첫 구간부터 시작한다.
4. 사용자는 기준음(도)을 듣고, 이어서 고른 구간을 **악보의 리듬대로**(♩= 80, 음 길이의 약 90%, 쉼표는 소리 없음) 들을 수 있다 ("문제 듣기"). "다시 듣기"는 구간만 다시 들려준다. 처음 끝까지 들은 뒤에 입력이 열린다.
   - 음높이 연습이므로 리듬 모드와 달리 마디 첫 박 강세를 두지 않는다 (모든 음이 같은 음량).
   - 구간이 쉼표로 시작하면, 기준음 다음 쉼 뒤에 그 쉼표 길이만큼 소리 없이 기다린 다음 첫 음을 낸다.
5. 사용자는 멜로디 모드와 같은 오선 입력으로 구간의 음높이를 순서대로 적는다 (음역 C4~G5, 빈칸 = 구간의 음 개수, 리듬은 적지 않음).
6. 사용자는 제출하면 음별 정답/오답과 함께 정답 구간을 악보 보기(리듬 포함)와 계이름으로 확인한다. "다음 문제"는 다음 구간으로 넘어가고, 마지막 구간 다음은 첫 구간이다 (구간이 하나뿐이면 같은 구간을 다시 낸다). 다른 악보를 고르면 첫 구간부터 시작한다.

#### 진행 흐름
- 연습: 악보 고르기 → 구간 고르기(기본 첫 구간) → 기준음(도) → 구간 재생(리듬대로) → 음높이 입력 → 제출 → 음별 채점 + 정답 구간 공개 → 다음 구간
- 만들기: [새 악보] → 제목·박자표 → 길이 고르고 오선 누르기 반복 → 저장 → 연습 화면으로 돌아와 그 악보가 선택됨

#### 채점 규칙
- 멜로디 모드(4-A)와 같다: 음별 채점(부분 점수), 이명동음 인정, 입력 개수 = 구간의 음 개수일 때만 제출.

### 4-F. 원곡 악보 형식 (확장 5)

**원칙: 앱은 곡을 바꾸지 않는다.** 내 악보가 원곡을 그대로 담고, 원래 조·음역·리듬·빠르기로 들려주고 보여 준다. 담을 수 없는 것이 있으면 몰래 고치지 않고 사용자에게 알린다. 확장 4의 "지금 틀 안" 제한(다장조, C4~G5, 음표 7종, 2/4·3/4·4/4, 12마디, 못갖춘마디 없음)을 없애는 것이 이 확장의 일이다. 확장 6(MusicXML 불러오기)은 이 형식으로 곡을 바꾸지 않고 옮겨 담는다.

남는 것은 청음 목적에서 오는 선택뿐이다: 한 선율(단선율)만 연습하고, 소리와 관계없는 표기(셈여림·아티큘레이션 등)는 담지 않는다. 연습 방식은 확장 4와 같이 **음높이만** 받아 적는다.

1. 악보는 다음을 담을 수 있다.
   - 조: 조표(♯·♭ 0~7개), 장조·단조, 곡 중간의 조 바꿈
   - 음높이: 음역 제한 없음(덧줄), 겹올림표·겹내림표 포함, 높은음자리표·낮은음자리표(곡 중간 변경 포함)
   - 길이: 온·2분·4분·8분·16분·32분음표와 같은 길이의 쉼표, 점·겹점, 붙임줄(마디를 넘는 음 포함), 잇단음표(셋잇단 등 n:m)
   - 박자: 단순박자(2/4·3/4·4/4 등)와 겹박자(6/8·9/8·12/8), 2/2, 곡 중간의 박자 바꿈, 못갖춘마디(첫 마디가 짧음)
   - 빠르기: 원래 빠르기(♩= n, 곡 중간 변경 포함). 직접 만든 악보의 기본값은 ♩= 80
   - 길이: 마디 수 제한 없음
   - 장조·단조는 조표만으로 알 수 없으므로 악보에 따로 적는다(조표와 함께 "장조/단조"). 직접 만든 악보는 다장조다.
   - 데이터는 확장 6에서 그대로 옮겨 담을 수 있게 MusicXML과 같은 단위로 둔다: 음높이 = 음이름·변화(-2~2)·옥타브, 길이 = 분수(온음표 기준), 붙임줄 시작/끝, 잇단음표 n:m, 마디마다 박자·조·음자리표·빠르기 바뀜.
2. 저장 형식을 새 버전으로 바꾼다 (`ltw.scores.v2`).
   - 예전 악보(v1)는 처음 열 때 새 형식으로 옮기고, 옮긴 악보는 그대로 연습·편집할 수 있다. 옮기지 못한 악보는 그 사실을 안내한다.
   - 불러올 때 악보마다 검증한다(음높이·길이 값, 마디 길이와 박자의 일치, 붙임줄 짝, 잇단음표 묶음). 깨진 악보만 빼고 안내한다.
   - 예시 악보는 새 형식의 기능을 보여 주는 공유저작물 곡들이다. 새 곡은 앞부분 4~16마디만 넣는다.
     - 반짝반짝 작은 별 (기존, 다장조 기본)
     - 엘리제를 위하여 앞부분 (베토벤 — 가단조, 3/8, 16분음표, 못갖춘마디)
     - 그린슬리브스 (영국 민요 — 단조, 6/8 겹박자, 점음표, 못갖춘마디)
     - 산왕의 궁전에서 (그리그 「페르 귄트」 — 낮은음자리표, 나단조 조표 기준 임시표 E♯·C♮)
     - 리듬 표기 연습곡 (이 앱용, 실제 곡 아님 — 붙임줄(마디 넘는 것 포함)·셋잇단 8분·4분음표·조 바꿈(다장조 → 사장조)·박자 바꿈(4/4 → 3/4 → 6/8)). 셋잇단·붙임줄이 든 곡을 정확히 옮길 수 없어 연습곡으로 대신함 (2026-10-31 사용자 결정)
     넣는 규칙은 확장 4와 같다(목록이 없을 때만). 나중에 더한 예시는 이미 목록이 있는 사용자에게도 한 번만 더해 준다(어떤 예시를 보여 줬는지 따로 기억하고, 지운 예시는 다시 넣지 않음). v1 저장소에서 옮겨 온 사용자도 같다. 새 곡은 기억으로 옮겨 적으므로 사용자가 악보와 소리를 확인한다.
3. 악보 보기는 원곡 표기 그대로 그린다: 음자리표, 조표, 박자표(바뀌는 마디에도), 덧줄, 겹임시표, 점·겹점, 붙임줄, 잇단음표 괄호와 숫자, 16·32분음표 꼬리와 빔(단순박자는 박 단위, 겹박자는 점4분 단위로 묶음).
   - 임시표는 조표를 기준으로 표준 표기한다: 조표와 다른 음에만 붙이고 마디 끝까지 이어지며, 조표 음으로 돌아가면 제자리표(♮). 붙임줄로 다음 마디에 이어진 음에는 다시 붙이지 않는다.
   - 넓은 화면 4마디·휴대폰 폭 2마디씩 줄을 나누는 규칙은 그대로 두고, 음이 많아 한 줄에 다 들어가지 않으면 그 줄은 더 적게 넣는다. 한 마디가 화면보다 넓으면 그 줄만 좌우로 스크롤한다(마디를 쪼개지 않는다).
4. 재생은 원래 조·음높이·빠르기로 한다.
   - 붙임줄로 이은 음은 한 번만 울리고 이은 길이만큼 이어진다. 잇단음표는 실제 길이로 나눠 울린다.
   - 빠르기 선택 [원래 빠르기 | 느리게(75%) | 아주 느리게(50%)] (⚙ 설정, 5번). 고른 값은 브라우저에 기억한다.
   - 기준음은 구간 시작 위치의 조로 정한다: 장조는 으뜸음 "도", 단조는 으뜸음 "라". 버튼 이름도 "기준음(도) 듣기" / "기준음(라) 듣기"로 바뀐다. 음높이는 구간의 음역에 가까운 옥타브로 한다.
5. 부분 연습: 사용자는 "악보" 패널의 **한 줄 악보 띠**에서 마디를 눌러 연습할 구간을 고른다.
   - 한 줄 악보 띠는 곡 전체를 한 줄로 그린 악보(원곡 표기, 마디 번호 표시)이고, 좌우로 밀어 본다. 높이가 고정되어 곡 길이와 관계없이 패널 높이가 변하지 않는다. 확장 4의 구간 칩 줄을 대신한다.
   - 길이 칩 [1마디 | 2마디 | 4마디 | 직접]. 1·2·4마디는 시작 마디만 누르면 그 길이만큼, "직접"은 시작 마디와 끝 마디를 차례로 누른다. 고른 구간은 악보 보기에 강조된다.
   - 고른 구간이 띠에서 보이도록 자동으로 스크롤한다.
   - 기본은 첫 마디(못갖춘마디면 그것부터)부터 2마디다. "다음 문제"는 같은 길이로 바로 뒤 구간으로 넘어가고, 끝 다음은 처음이다. 쉼표만 있는 구간은 건너뛴다.
   - 구간 안의 음 개수에는 제한이 없다. 붙임줄로 이은 음은 한 음으로 센다. 구간 경계에 걸친 붙임줄 음은 시작하는 구간에 속한다.
   - 악보마다 마지막으로 고른 구간과 길이를 기억한다.
   - "악보" 패널은 제목 줄(오른쪽 끝에 ⚙), [악보 선택 | 새 악보 | 편집] 줄, 길이 칩, 한 줄 악보 띠로 이루어진다. (⚙은 악보 고르기 줄이 320px에서 꽉 차므로 제목 줄에 둠, 2026-10-31) 다른 모드의 "난이도" 패널도 같은 높이로 맞춰, 모드를 바꿔도 받아 적기 영역이 움직이지 않는다 (4-0-3).
   - ⚙ 설정을 누르면 작은 창에서 빠르기와 계이름 방식을 바꾼다(브라우저 확인창이 아닌 페이지 안의 창, 바깥을 누르거나 Esc로 닫힘). 설정은 모든 악보에 함께 적용된다.
6. 받아 적기는 확장 4처럼 오선에 음높이를 순서대로 찍되, 원곡에 맞춘다.
   - 받아 적기 오선은 그 악보의 음자리표와 (구간 시작 위치의) 조표를 보여 주고, 줄/칸을 누르면 조표가 적용된 음이 들어간다(사장조에서 파 자리 = 파#). 임시표 토글은 ♯/♭/♮ 세 가지이고, 켜면 조표 대신 그 임시표가 붙는다.
   - 입력할 수 있는 음역은 그 악보 전체의 음역보다 위아래로 넉넉히 넓게 한다(정답 구간의 음역을 알려 주지 않도록 악보 단위로 정한다).
   - 음이 많아 화면을 넘치면 오선과 계이름 줄이 함께 좌우로 스크롤된다. 음을 찍으면 다음 빈칸이 보이도록 자동으로 따라간다. 스크롤하려고 미는 동작은 음 입력으로 처리하지 않는다.
   - 계이름 표시는 [이동도 | 고정도] 중 사용자가 ⚙ 설정에서 고른다(기본: 이동도). 이동도는 장조 으뜸음 = 도, 단조 으뜸음 = 라(조 바꿈을 따라감), 고정도는 C = 도. 고른 값은 브라우저에 기억하고, 받아 적기 계이름 줄과 결과의 계이름에 함께 쓴다. 멜로디·화성 모드(다장조)는 두 방식이 같으므로 바뀌지 않는다.
7. 결과는 확장 4와 같이 음별 정답/오답과 정답 구간 악보(원곡 표기, 리듬 포함)와 계이름을 보여 준다. 긴 구간은 정답 악보와 계이름 줄도 좌우로 스크롤된다.
8. 편집기는 확장 7에서 새 형식에 맞게 넓힌다(4-H). 그 전까지는:
   - 지금 편집기로 만들 수 있는 악보(다장조·음표 7종 등)는 그대로 만들고 고칠 수 있다.
   - 편집기가 다룰 수 없는 기능이 든 악보는 편집기를 열 수 없고 이유를 안내한다(악보를 편집기 범위로 바꾸지 않는다). 예시 악보 중 새 곡들이 여기에 해당한다. 이런 악보는 [편집] 자리가 [삭제]로 바뀌어(두 번 눌러 확정) 지울 수 있다.
   - 편집기로 저장한 악보는 v2 형식으로 저장되고, 연습 화면의 새 기능(한 줄 악보 띠, 원래 빠르기 ♩= 80, 계이름 설정)을 똑같이 쓴다.

#### 진행 흐름
- 연습: 악보 고르기 → 길이 칩 + 한 줄 악보 띠에서 마디 눌러 구간 고르기(기본 처음 2마디) → (빠르기·계이름 설정) → 기준음(도/라) → 구간 재생(원래 조·리듬·빠르기) → 음높이 입력(필요하면 좌우 스크롤) → 제출 → 음별 채점 + 정답 구간 공개 → 다음 구간

#### 채점 규칙
- 확장 4와 같다: 음별 채점(부분 점수), 이명동음 인정(겹임시표 음도 같은 음높이면 정답), 입력 개수 = 구간의 음 개수(붙임줄 묶음은 하나)일 때만 제출.

### 4-G. MusicXML 불러오기 (확장 6)

사용자가 MuseScore 등에서 내보낸 MusicXML 파일(.musicxml/.xml, 압축 .mxl)을 불러와, 고른 한 성부를 **곡을 바꾸지 않고** 확장 5 형식으로 옮겨 담는다. 연습은 확장 5와 같이 음높이만 받아 적는다. 확장 5 형식이 담지 못하던 표기(알토·테너·옥타브 음자리표, 64분음표, 잇단음표 안의 잇단음표, 곡 중간의 짧은 마디, 긴 제목, 화음, 꾸밈음, 도돌이표 기호)는 형식을 넓혀 담는다. 그래도 담을 수 없는 파일(혼합 박자·무박자, score-timewise 형식)은 불러오지 않고 이유를 알린다. 소리의 높이·길이와 관계없는 표기(셈여림·아티큘레이션·가사·운지 등)는 확장 5처럼 담지 않는다.

1. 사용자는 "악보" 패널의 [새 악보]를 눌러 페이지 안의 작은 창에서 [직접 만들기 | 파일 불러오기]를 고른다.
   - 작은 창은 ⚙ 설정 창과 같은 방식이다(브라우저 확인창이 아님, 바깥을 누르거나 Esc로 닫힘). [직접 만들기]는 지금의 편집 화면을 연다. 패널의 줄과 높이는 바뀌지 않는다 (4-0-3).
   - [파일 불러오기]는 파일 선택(`<input type="file">`, .musicxml/.xml/.mxl)을 연다. 파일은 브라우저 안에서만 읽고 어디로도 보내지 않는다.
   - .mxl은 브라우저 안에서 압축을 풀고(META-INF/container.xml이 가리키는 악보 파일), UTF-8·UTF-16 파일을 모두 읽는다.
   - MusicXML이 아니거나 깨진 파일, score-timewise 형식, 음높이가 있는 파트가 없는 파일은 이유를 안내하고 아무것도 저장하지 않는다.
2. 사용자는 작은 창에서 연습할 선율을 고른다.
   - 파트(악기 이름) 목록을 보여 준다. 타악기처럼 음높이가 없는 파트는 목록에서 빼고 그 사실을 적는다.
   - 고른 파트에 보표나 성부가 둘 이상이면(예: 피아노 오른손·왼손, 한 보표의 두 성부) 보표·성부도 고른다. 하나뿐이면 묻지 않는다.
   - [불러오기]를 누르면 고른 성부 하나만 새 악보로 저장하고, 연습 화면으로 돌아와 그 악보가 선택된다(기본 구간 = 처음 2마디).
   - 저장에 실패하면 확장 4·5와 같이 안내하고 이번 방문 동안 메모리에서 쓴다.
3. 옮기는 규칙: 원곡을 그대로 옮긴다.
   - 제목은 파일의 곡 제목(work-title → movement-title)을, 없으면 파일 이름을 쓴다. 다른 악보와 같은 제목이면(편집기와 같은 비교, 4-H-1) 뒤에 " (1)", " (2)" …에서 겹치지 않는 가장 작은 번호를 붙여 저장하고 알린다 (2026-10-31 사용자 요청). 제목 길이 상한을 넓히고, 화면에서는 넘치면 줄임표로 보여 준다(편집기에서 직접 쓰는 제목은 30자 그대로).
   - 음높이·길이·점·쉼표·붙임줄·잇단음표·조표(+장조/단조)·박자·음자리표·빠르기와 그 바뀜, 못갖춘마디를 그대로 옮긴다. 마디 번호는 파일의 번호를 따른다.
   - 이조악기 파트(transpose가 있는 파트, 예: B♭ 클라리넷)는 **실음**으로 옮긴다(악보와 소리 모두). 불러온 뒤 "실음으로 옮겼어요"를 알린다.
   - 빠르기 표시가 없으면 ♩= 120(MusicXML 기본값)으로 한다. 점4분음표 등 다른 박 단위의 빠르기는 4분음표 기준으로 환산한다.
   - 조에 장조·단조 표시가 없으면 장조로 본다. 교회 선법(도리아 등)은 조표는 그대로 두고 장조로 보며, 그 사실을 알린다.
   - 고른 성부가 비어 있는 자리(그 성부가 없는 마디, 건너뛴 박)는 쉼표로 채운다. 마디 쉼표는 그 마디 길이의 쉼표다.
   - 빔·기둥 방향·친절 임시표는 파일 정보를 쓰지 않고 확장 5의 규칙대로 그린다(소리와 관계없음).
   - 불러온 뒤 알림은 "악보" 패널의 고정된 안내 자리에 한 줄로 보인다.
4. 형식을 넓혀 담는 것 (저장 키는 `ltw.scores.v2` 그대로, 새 값은 선택 필드라 기존 악보와 호환)
   - 음자리표: 높은음·낮은음 + 알토·테너, 옥타브 음자리표(높은음 8vb·8va, 낮은음 8vb). 음높이는 실제 소리로 담고 그리는 자리만 옮긴다.
   - 길이: + 64분음표(와 같은 길이의 쉼표). 잇단음표 안의 잇단음표(길이는 비율을 곱하고, 괄호와 숫자는 단계별로 그림).
   - 곡 중간의 짧은 마디(도돌이표 앞뒤로 나뉜 마디 등): 짧게 그린다. MusicXML이 번호를 세지 않는 마디(implicit)로 적은 것은 번호를 세지 않고 그리지 않는다.
   - 마디 중간의 음자리표·빠르기 바뀜: 그 음부터 바뀐 음자리표로 그리고 바뀐 빠르기로 들려준다.
   - 박자 기호 C·¢는 기호 그대로 그린다.
   - 화음: 한 음에 함께 울리는 음들을 담는다(음마다 붙임줄). 악보 보기는 화음 그대로 그리고, 재생도 화음으로 울린다(음 개수가 많아도 소리가 깨지지 않게 음량을 나눔).
   - 꾸밈음(앞꾸밈음·사선 꾸밈음): 박자 길이를 차지하지 않는다. 작은 음표로 그리고, 재생은 종류별 관례대로 뒤 음으로 이어지게(레가토) 울린다: 사선 꾸밈음(짧은 앞꾸밈음)은 박 바로 앞에서 아주 짧게(0.03초) 붙여 치고 뒤 음은 박 그대로. 사선이 없어도 16분음표 이하로 짧게 적힌 꾸밈음은 같은 길이로 박 위에서 붙여 치고, 8분음표 이상으로 적힌 사선 없는 꾸밈음(긴 앞꾸밈음)만 박 위에서 적힌 길이만큼(뒤 음 길이의 절반을 넘지 않게) 뒤 음의 시간을 빌린다. 뒤 음은 빌린 만큼 늦게 시작한다. (2026-10-31 사용자 결정·청취 의견: 따로 끊겨 들리지 않게, 짧은 꾸밈음은 "툭" 하고 붙게)
   - 도돌이표(시작·끝), 1·2번 괄호, D.C./D.S./Fine/Coda/Segno: 악보 보기와 한 줄 악보 띠에 그린다. 재생과 구간은 적힌 순서를 따르고, 반복은 사용자가 구간을 다시 골라 연습한다.
   - 편집기(확장 7 전)는 이 기능들이 든 악보를 열 수 없고 이유(예: "화음", "꾸밈음")를 안내하며, [편집] 자리가 [삭제]로 바뀐다 (4-F-8과 같음).
5. 화음이 든 악보의 받아 적기
   - 받아 적는 음은 화음의 **맨 위 음**(선율 청음, 기본) 또는 **맨 아래 음**(베이스 청음)이다. 화음이 든 악보를 고르면 ⚙ 설정 창에 [맨 위 음 | 맨 아래 음]이 나타나고, 악보마다 브라우저에 기억한다.
   - 받아 적기 빈칸·입력 음역·기준음 옥타브는 고른 줄의 음으로 정한다(화음 전체가 아님).
   - 결과의 정답 구간 악보는 화음 그대로 보여 주고, 계이름 줄은 고른 줄의 음이다.
6. 꾸밈음도 들리는 음이므로 받아 적는다: 빈칸 하나씩, 뒤 음 앞 순서로 들어가고 다른 음과 같이 채점한다(빈칸은 다른 음과 같은 모양). 화음 꾸밈음은 5번처럼 고른 줄의 음이다. (2026-10-31 사용자 결정: 들리는데 정답에 없으면 헷갈림)

#### 진행 흐름
- 불러오기: [새 악보] → [파일 불러오기] → 파일 고르기(.musicxml/.xml/.mxl) → 파트 → (여럿이면) 보표·성부 고르기 → [불러오기] → 알림 + 그 악보가 선택된 연습 화면
- 연습: 확장 5와 같다 (화음이 든 악보는 ⚙에서 맨 위/맨 아래 음 선택)

#### 채점 규칙
- 확장 5와 같다: 음별 채점(부분 점수), 이명동음 인정, 붙임줄 묶음은 한 음, 입력 개수 = 구간의 음 개수일 때만 제출.
- 화음은 ⚙에서 고른 줄(맨 위 음 / 맨 아래 음)의 음 하나를 정답으로 한다. 꾸밈음도 한 음으로 센다.

### 4-H. 편집기 넓히기 (확장 7)

사용자가 확장 5·6 형식의 **모든 표기**를 편집기에서 직접 넣고, 만든 악보와 불러온 악보를 어디서든 고친다. 편집 방식은 MuseScore처럼 **커서로 음을 골라 그 자리에서 고치는** 방식이고, 마디의 박은 늘 맞게 유지한다(덮어쓰기 + 쉼표 채우기). 데스크톱에서는 키보드로도 입력한다. 이 확장으로 모든 악보를 편집기로 열 수 있게 되어, 확장 5·6에서 편집기 범위 밖 악보에 [편집] 대신 보이던 [삭제]는 없어진다(삭제는 편집 화면의 [삭제]로 한다). 연습(받아 적기·채점)은 바뀌지 않는다.

1. 사용자는 [새 악보] → [직접 만들기], 또는 고른 악보의 [편집]으로 편집 화면을 연다.
   - 편집 화면은 확장 4처럼 "악보" 패널 아래의 듣기·받아 적기·결과 자리를 대신한다. 열면 재생 중인 소리를 멈추고, 편집 중에 모드 탭을 바꾸면 [취소]와 같이 저장하지 않은 입력을 버린다 (확장 4 규칙 그대로).
   - 새 악보는 4/4·다장조·높은음자리표·♩= 120, 온쉼표 한 마디로 시작한다. 이 값은 아래 "마디" 도구에서 바꾼다.
   - 제목은 100자까지(불러온 악보의 제목 상한과 같음), 공백만 있으면 제목이 없는 것으로 본다. 다른 악보와 같은 제목(앞뒤·연속 공백과 영문 대소문자는 무시하고 비교)으로는 저장하지 않고, 제목 칸 아래에 "같은 제목의 악보가 있어요"를 보인다. 고치는 악보 자신의 제목은 겹침으로 보지 않는다 (2026-10-31 사용자 요청).
   - 편집 화면 위쪽에 **악보 보기**(확장 5의 그리기, 넓은 화면 4마디·휴대폰 2마디씩 여러 줄)가 있고, 고른 음(커서)이 강조된다. 음을 누르면 그 음이 커서가 된다. 화음은 누른 음머리까지 고른다.
2. 사용자는 길이를 고르고 음높이를 넣어 커서 자리에 음을 적는다.
   - 길이 버튼: 온·2분·4분·8분·16분·32분·64분음표, 점(한 번 더 누르면 겹점), 쉼표. 고른 길이는 다음 입력에 쓰이고, 커서 음에 바로 적용할 수도 있다.
   - 음높이: 그 자리의 음자리표로 된 입력 오선(덧줄 3개씩 위아래, [옥타브 ↑↓]로 더 높거나 낮게)의 줄·칸을 누르면, 조표와 그 마디 앞의 임시표가 적용된 음(악보에 보이는 대로)이 들어간다. 임시표 토글 ♯/♭/♮(켜면 그 임시표가 붙음), 넣은 뒤 [반음 ↑↓]로 고친다. 겹올림·겹내림도 반음 ↑↓로 만들 수 있다.
   - 음을 넣으면 그 음 소리를 짧게 들려주고 커서가 다음 자리로 간다. 마지막 마디 끝에서 넣으면 같은 박자의 마디가 새로 생긴다.
   - **덮어쓰기**: 넣은 음이 커서 자리의 음보다 길면 그만큼 뒤의 음을 덮어쓰고(일부만 덮인 음의 나머지는 쉼표), 짧으면 남은 자리를 쉼표로 채운다. 그래서 마디의 박은 늘 맞고 다른 마디는 그대로다. 마디 끝을 넘는 길이는 그 자리에서 고를 수 없다(붙임줄로 나눠 적는다).
   - [지우기]는 커서 음을 같은 길이의 쉼표로 바꾼다. 쉼표를 지우면 바뀌지 않는다. 마디 지우기·마디 넣기는 "마디" 도구에서 한다.
   - [되돌리기 | 다시 하기]: 편집 화면을 연 뒤의 바뀜을 100번까지 되돌린다. 닫으면 기록을 버린다.
3. 사용자는 나머지 표기를 도구로 넣는다. 도구는 [음표 | 마디 | 기호] 세 묶음의 탭으로 나눠, 휴대폰(320px)에서도 한 화면에 들어가고 편집 화면 높이가 탭에 따라 바뀌지 않는다.
   - 음표: 붙임줄(커서 음과 다음 음의 같은 높이를 잇는다. 다음 음에 같은 높이가 없으면 안내), 잇단음표(고른 길이를 단위로 [3 | 5 | 6 | 7 | 직접 n:m] — 8분 + 3잇단 = 4분 자리의 8분 셋잇단, 커서 자리부터 묶음으로 바꾸고 안을 쉼표로 채움, 묶음 안에서 한 번 더 넣으면 겹잇단음표, [잇단 풀기]로 쉼표로 되돌림), 화음(켜면 오선을 누를 때 커서 음에 그 높이를 더하고, 이미 있는 높이면 뺌), 꾸밈음(켜면 커서 음 앞에 작은 음표로 넣음, 사선 토글).
   - 마디(커서가 있는 마디부터): 박자(분자 1~32 · 분모 1/2/4/8/16/32, C·¢ 기호), 조표(♯·♭ 0~7, 장조/단조), 음자리표(8종, 마디 첫머리 또는 커서 음부터), 빠르기(♩= 5~1000, 마디 첫머리 또는 커서 음부터), 못갖춘마디(첫 마디 길이), 짧은 마디(마디 길이 줄이기, 번호 세지 않기), 마디 넣기(앞에)·마디 지우기, 첫 마디 번호.
   - 기호: 도돌이표 시작·끝, 겹세로줄·끝세로줄, 1·2번 괄호(시작 마디부터 끝 마디까지, 번호 글자, 닫힘/열림), 세뇨·코다, D.C./D.S./Fine/To Coda 등 글자(마디 첫머리 또는 끝).
   - 박자를 바꾸면 그 마디부터 다음 박자 바뀜 전까지의 마디마다: 길어지면 끝을 쉼표로 채우고, 짧아지면 넘치는 끝의 음을 지운다(지운 음 개수를 알리고, 되돌리기로 되살릴 수 있다). 조표·음자리표를 바꿔도 음높이(실제 소리)는 그대로이고 그려지는 모양만 바뀐다.
4. 데스크톱에서는 키보드로도 입력한다(같은 동작은 모두 화면 버튼으로도 된다). 제목 입력칸에 글을 쓰는 동안에는 단축키가 동작하지 않는다.
   - A~G: 그 음이름의 음(커서 앞 음에서 가장 가까운 옥타브), Shift+A~G: 화음에 더하기, Ctrl+↑↓: 옥타브, ↑↓: 반음
   - 1~7: 64분·32분·16분·8분·4분·2분·온음표(MuseScore와 같은 번호), .: 점, 0: 쉼표, +: 붙임줄, Alt+3(5·6·7): 잇단음표 (MuseScore는 Ctrl+3이지만 브라우저가 Ctrl+숫자를 탭 바꾸기로 쓰므로 Alt, 2026-10-31 44단계)
   - ←→: 커서 이동, Ctrl+←→: 마디 이동, Delete: 지우기, Ctrl+Z / Ctrl+Y: 되돌리기 / 다시 하기
5. 사용자는 편집 중에 들어 본다: [듣기]는 커서가 있는 마디부터 끝까지(또는 [멈춤]까지) 원래 빠르기로 들려준다. 재생은 연습 화면과 같은 규칙(적힌 순서, 화음·꾸밈음 포함)이다.
6. [저장]은 제목이 있고 음이 하나 이상 있으면 된다(마디 박은 늘 맞으므로 따로 검사하지 않는다). 저장하면 연습 화면으로 돌아와 그 악보가 선택되고, 구간은 확장 5 규칙대로 다시 고른다. [삭제]는 확장 4처럼 두 번 눌러 확정한다.

#### 진행 흐름
- 만들기·고치기: [새 악보] → [직접 만들기] (또는 [편집]) → 음 누르기(커서) → 길이 고르기 → 음높이 넣기(오선/키보드) → 도구 탭으로 표기 넣기 → [듣기]로 확인 → [저장] → 그 악보가 선택된 연습 화면
- 연습: 확장 5·6과 같다

#### 채점 규칙
- 확장 5·6과 같다 (편집기는 채점을 바꾸지 않는다).

### 4-I. 실제 악기 소리 (확장 8)

네 모드의 소리(기준음·문제·다시 듣기·결과·편집기 듣기)를 삼각파 합성 대신 **실제 악기 녹음**으로 낸다. 기본은 그랜드 피아노이고, 소리 내는 방식이 서로 겹치지 않는 네 악기 — 바이올린(활로 켬, 지속), 플루트(입김, 지속·맑음), 마림바(나무를 두드림, 짧게 사라짐), 하프(줄을 뜯음, 빨리 사라짐) — 중에서 바꿀 수 있다. 음높이·박자·빠르기·연습 내용은 바뀌지 않는다. 악기마다 몇 음만 녹음해 두고(단3도 간격 안팎), 사이 음은 가장 가까운 녹음의 높이를 바꿔 낸다.

1. 사용자는 ⚙ 설정 창에서 악기를 고른다.
   - ⚙ 버튼은 네 모드 모두의 패널 제목 줄에 보인다. 악기 고르기는 모든 모드에 함께 적용되고, 빠르기·계이름·화음 줄 설정은 지금처럼 내 악보에서만 보인다. 패널 높이와 받아 적기 영역 위치는 바뀌지 않는다 (4-0-3).
   - 악기: [피아노 | 바이올린 | 플루트 | 마림바 | 하프], 기본 피아노. 고른 악기는 브라우저에 기억한다(실패하면 피아노).
   - 악기를 고르면 그 악기로 짧은 음계(도~높은 도 위로)를 미리 들려준다.
   - 녹음은 고를 때 불러온다(피아노는 페이지와 함께). 불러오는 동안은 설정 창에 "불러오는 중"을 보이고, 그사이 재생은 지금의 합성음으로 낸다. 불러오지 못하면 그 사실을 알리고 합성음으로 계속한다.
   - 설정 창 맨 아래에 녹음 출처를 한 줄로 적는다(피아노: Salamander Grand Piano, Alexander Holm, CC BY 3.0 / 나머지: VSCO 2 Community Edition, Versilian Studios, CC0).
2. 소리를 내는 규칙
   - 모든 소리(기준음, 멜로디·화음·리듬·내 악보 구간, 펼쳐 듣기, 편집기 듣기·음 넣을 때 소리)가 고른 악기로 난다. 리듬 모드의 카운트인 클릭(박 세기)만 지금 소리 그대로다.
   - 고른 악기가 낼 수 없는 음역의 음도 그 악기의 가장 가까운 녹음을 늘려서 낸다(MuseScore·일반 MIDI 음원과 같은 방식). 음높이는 정확하고, 음역에서 멀수록 음색이 조금 어색해진다. 설정 창에 "음역 밖의 음은 녹음을 늘려서 내요"를 한 줄로 알린다.
   - 음은 적힌 길이(지금처럼 길이의 90% 등)에서 짧게 줄어들며 끝난다. 피아노·마림바·하프는 녹음처럼 저절로 사라지고, 바이올린·플루트는 녹음보다 긴 음이면 녹음의 고른 부분을 되풀이해 이어 낸다.
   - 화음·여러 음이 동시에 날 때는 지금처럼 음 개수에 따라 음량을 나눠 소리가 깨지지 않게 한다. 리듬 모드의 마디 첫 박 강세도 음량으로 그대로 낸다.
   - 녹음은 한 가지 세기(mf)만 쓴다.

#### 진행 흐름
- 고르기: ⚙ → 악기 고르기 → (불러오는 중) → 미리 듣기 → 모든 모드에서 그 악기로 연습
- 연습: 각 모드와 같다

#### 채점 규칙
- 바뀌지 않는다 (소리만 바뀜).

### 4-J. 리듬 모드 넓히기 (확장 9)

리듬 모드에 **[기본 | 심화]**를 둔다. 기본은 지금 리듬 모드(4-D) 그대로이고, 심화는 16분음표·점8분음표·8분쉼표 등 모든 쉼표·셋잇단음표(8분·4분)·붙임줄과 겹박자(6/8·9/8·12/8)를 받아 적는다. 음높이는 다루지 않는다(한 가지 높이). 두 리듬 모두 같은 한 줄 보표(일반 음표머리)로 그리고, 채점은 **소리 기준**으로 바꾼다. 셋잇단 밖의 잇단음표, 16분 셋잇단, 32분음표, 겹점, 그 밖의 박자는 다루지 않는다.

1. 사용자는 리듬 모드의 난이도 패널 제목 줄에서 [기본 | 심화]를 고른다.
   - 화성 모드의 [3화음 | 7화음]과 같은 모양·자리이고, 바꾸면 그 종류의 새 문제가 나온다. ⚙ 버튼과 함께 320px 한 줄에 들어간다.
   - 심화의 난이도 설명은 그 단계에서 새로 나오는 표기를 적는다(어려움은 마디 수를 적지 않는다, 4-D와 같음).
   - 패널 높이와 받아 적기 영역 위치는 바뀌지 않는다 (4-0-3).
2. 사용자는 카운트인을 듣고 리듬을 듣는다 ("문제 듣기", "다시 듣기"는 카운트인 포함, 4-D와 같음).
   - 빠르기: 기본은 지금처럼 ♩=80. 심화 쉬움·중간은 단순박자 ♩=80, 겹박자 ♩.=60. 심화 어려움은 박자표를 맞히는 문제이므로 단순박자 ♩=60, 겹박자 ♩.=60으로 한 박을 모두 1초로 맞춰, 카운트인 속도로 박자가 드러나지 않게 한다.
   - 카운트인: 쉬움·중간은 박자표에 맞춘 1마디를 박 단위로 센다(겹박자는 점4분음표 박: 6/8은 2번, 9/8은 3번, 12/8은 4번), 첫 박은 높은 소리. 어려움은 강세 없는 4번(한 박 1초).
   - 붙임줄로 이은 음은 한 번만 소리 내고 이은 길이만큼 이어 낸다. 셋잇단음표는 정확히 3등분한 길이로 낸다. 각 마디 첫 박 강세, 음 길이의 약 90%, 고른 악기 소리는 4-D·4-I와 같다.
3. 사용자는 음표 버튼으로 들은 리듬을 순서대로 입력한다.
   - 심화 버튼: 길이 [온 | 2분 | 4분 | 8분 | 16분] + 켜 두는 버튼 [점 | 쉼표 | 셋잇단 | 붙임줄] (편집기(4-H)와 같은 방식). 휴대폰 폭에서는 5열 × 2줄. 난이도에 따라 쓰는 버튼만 보인다(쉬움: 셋잇단·붙임줄 없음).
   - [점]·[쉼표]는 켜 둔 동안 넣는 길이에 적용된다. 점은 홑점만.
   - [셋잇단]을 켜면 다음에 넣는 음표·쉼표가 셋잇단 길이(2/3)가 되고, 첫 음의 길이로 묶음이 정해진다(8분 셋잇단 = 4분음표 한 박, 4분 셋잇단 = 2분음표). 묶음이 다 찰 때까지 이어지며, 묶음 중간에는 끌 수 없고 묶음에 안 들어가는 길이는 누를 수 없다. 묶음이 차면 셋잇단은 다시 꺼진다.
   - [붙임줄]을 누르면 바로 앞 음표와 다음에 넣는 음표가 이어진다(마디선을 넘어도 된다). 쉼표는 잇지 않는다.
   - 마디는 자동으로 나뉘고, 지금 마디의 남은 길이에 안 들어가는 길이는 누를 수 없다(마디를 넘는 길이는 붙임줄로 나눠 적는다). 마지막 음 지우기 / 전체 지우기는 붙임줄·셋잇단 상태도 함께 되돌린다.
   - 어려움의 박자표 버튼: 기본 [2/4 | 3/4 | 4/4], 심화 [2/4 | 3/4 | 4/4 | 6/8 | 9/8 | 12/8].
   - 기본은 지금 버튼(종류마다 하나, 최대 7개)과 입력 규칙 그대로다.
4. 사용자는 한 줄 보표에서 입력한 리듬을 본다.
   - 기본과 심화가 같은 그림(내 악보의 악보 그리기를 한 줄 보표로)을 쓴다: 일반 음표머리, 기둥 위, 빔(단순박자는 박 단위, 겹박자는 점4분음표 단위), 셋잇단 숫자·괄호, 붙임줄, 쉼표 모양.
   - 휴대폰 폭의 줄 나눔, 진행 상황 줄("3마디 · 남은 박 1"), 지금 마디 강조, 어려움의 두 줄 높이 고정은 4-D와 같다. 심화의 9/8·12/8은 한 줄에 한 마디이고, 보표 높이가 두 줄을 넘지 않도록 9/8·12/8 문제는 2마디까지, 입력도 2마디까지다.
5. 사용자는 제출하면 마디별 정답/오답, (어려움) 박자표 정답/오답, 정답 리듬 보표(표준 표기)를 확인한다. "다음 문제"는 같은 종류·난이도의 다른 리듬이다.

#### 진행 흐름
- [기본 | 심화] 고르기 → 난이도 → 카운트인 → 리듬 재생 → (어려움: 박자표 고르기) → 음표 버튼으로 입력 → 제출 → (어려움: 박자표 채점) 마디별 채점 + 정답 리듬 공개 → 다음 문제

#### 문제 구성 (심화, `js/data/rhythms.js`)
- 쉬움: 2마디, 2/4·3/4·4/4, 기본 어려움의 표기 + 16분음표·점8분음표·8분쉼표 (5개 이상)
- 중간: 2마디, + 셋잇단음표(8분·4분)·붙임줄·6/8 (5개 이상)
- 어려움: 3~4마디(9/8·12/8은 2마디), + 9/8·12/8, 박자표도 고름 (5개 이상)
- 기본 문제(4-D)는 그대로 두고 같은 데이터 형식(악보 형식 v2의 음표)으로 옮긴다.

#### 채점 규칙 (기본·심화 모두)
- 마디별로 채점한다(부분 점수). **소리 기준**: 마디 안에서 음이 시작하는 자리, 소리가 이어지는 구간(붙임줄로 이은 길이, 마디선에서 나눔), 쉬는 구간이 정답과 모두 같으면 그 마디가 정답이다. 그래서 4분음표와 8분음표⌒8분음표처럼 같은 소리를 다르게 적어도 정답이다(기본은 같은 소리를 다르게 적을 방법이 없어 결과가 지금과 같다).
- 제출 조건과 어려움 규칙(박자표가 틀리면 모든 마디 오답, 모자라거나 넘치는 마디)은 4-D와 같다. 박자표는 소리가 같아도(예: 6/8과 3/4) 고른 박자표가 정답과 같아야 한다.
- 결과의 정답 보표는 데이터에 적힌 표준 표기로 보여 준다.

### 4-K. 악보 자동 계이름 표시 (확장 10)

"계이름을 귀찮게 적는 일 없애기"(2번 목적)를 이룬다. 내 악보의 곡을 **[보기] 화면**에서 여러 줄 악보로 보여 주고, 음표마다 계이름을 자동으로 단다. 인쇄(또는 PDF 저장)할 수 있다. 받아 적기 결과의 정답 구간 악보에도 계이름을 단다. 연습 중(악보 띠, 받아 적기)에는 답이 드러나므로 계이름을 보이지 않는다. 편집기, 재생·따라가기, 가사는 다루지 않는다.

1. 사용자는 내 악보 패널의 [보기]를 눌러 고른 악보를 연다.
   - [보기]는 [새 악보 | 편집] 옆에 있다. 320px에서도 한 줄에 들어간다(악보 고르기 상자가 좁아져도 제목은 말줄임).
   - 보기 화면은 편집기처럼 듣기·받아 적기·결과 자리를 대신한다. 맨 위에 제목과 [인쇄] [닫기]. 모드를 바꾸거나 다른 악보를 고르면 닫힌다(고른 악보로 다시 열 수 있음).
   - 악보 전체를 여러 줄(편집기와 같은 그림: 넓은 폭 한 줄 4마디, 휴대폰 폭 2마디 안팎)로 보여 주고, 음표마다 아래에 계이름을 단다.
   - 패널 높이와 받아 적기 영역 위치는 바뀌지 않는다 (4-0-3).
2. 계이름을 다는 규칙
   - ⚙의 계이름 설정 [이동도 | 고정도]를 따른다. 이동도는 조표의 장조 으뜸음이 도, 단조는 으뜸음이 라이고, 곡 중간에 조가 바뀌면 그 마디부터 새 조로 읽는다. 조표에서 벗어난 음은 ♯/♭을 붙인다(예: 파♯). 고정도는 C가 도이고 음의 임시표를 붙인다. 보기 화면이 열린 채 설정을 바꾸면 바로 다시 그린다.
   - 붙임줄로 이어진 뒤 음(새로 치지 않는 음)과 쉼표에는 달지 않는다.
   - 화음은 모든 음의 계이름을 위에서 아래 순서로 세로로 쌓는다. 꾸밈음은 작은 글씨로 단다.
   - 계이름은 줄마다 악보 아래 같은 높이(가사 자리)에 적고, 글자끼리 겹치지 않게 음표 간격을 넓힌다.
3. 사용자는 [인쇄]로 브라우저의 인쇄 창을 연다(PDF 저장 포함). 인쇄 모양은 제목과 계이름 달린 악보만 있고(버튼·패널·탭 없음), 줄이 쪽 너비에 맞으며 한 줄이 두 쪽으로 잘리지 않는다.
4. 받아 적기 결과의 "정답 구간" 악보에도 음표 아래 계이름을 단다. 정답/오답 색은 계이름 글자에 칠하고, 그 아래 따로 있던 계이름 칩 줄은 없앤다(한 곳에서 본다). 멜로디·화성 모드 결과는 바뀌지 않는다.

#### 진행 흐름
- 보기: 악보 고르기 → [보기] → 계이름 달린 악보 → ([인쇄]) → [닫기]
- 연습: 지금과 같다. 제출 뒤 결과의 정답 구간에 계이름

### 내 악보 — 악보 형식과 표기

- 내 악보에 여러 파트·성부를 함께 저장하기, 화음 전체 받아 적기 — 불러올 때 고른 한 성부만 저장하고, 화음은 담되 받아 적기는 맨 위/맨 아래 한 줄 (확장 6, 화성 청음은 "청음 연습의 종류"의 화성 진행 항목)
- 셈여림·아티큘레이션·운지 등 소리의 높이·길이와 관계없는 표기 — 받아 적기 대상이 아니라 담지 않는다
- 파일의 빔·기둥 방향·친절 임시표 표기 재현 — 확장 5의 표기 규칙으로 그린다 (확장 6)

## 7. 기술 조건

- 결과물 형태: 브라우저에서 바로 여는 정적 웹앱 (서버 없이 파일만으로 동작)
- 사용할 도구/언어: HTML/CSS/JS. 음 재생은 Web Audio API로 합성음 생성 (별도 음원 파일 불필요)
- 지켜야 할 조건: 로그인·서버 없이 index.html을 더블클릭해서(file://) 열어도 작동해야 함
  - 그래서 ES 모듈(`import`)과 `fetch`로 파일 읽기는 쓰지 않는다 (file://에서 브라우저가 막음). 일반 `<script>` 태그를 쓰고, 멜로디 패턴·화음·리듬 데이터는 JS 파일 안에 둔다.
  - 내 악보 저장은 브라우저의 localStorage만 쓴다. 저장소를 쓸 수 없을 때(사생활 보호 모드 등)도 앱이 멈추지 않아야 한다.
  - 확장 5부터 악보 저장 키는 `ltw.scores.v2`이고, v1 악보는 옮겨 쓴다. 빠르기·계이름 설정과 악보별 마지막 구간도 localStorage에 둔다(실패해도 기본값으로 동작).
  - 확장 6의 파일 읽기는 `<input type="file">` + FileReader(또는 File.arrayBuffer)만 쓴다(file://에서 동작, fetch 없음). XML은 브라우저 내장 DOMParser로 읽고, .mxl(ZIP)은 외부 라이브러리 없이 ZIP 구조를 직접 읽어 브라우저 내장 DecompressionStream('deflate-raw')으로 푼다. 불러온 악보도 `ltw.scores.v2`에 저장하고(새 값은 선택 필드), 악보별 화음 받아 적기 줄(맨 위/맨 아래)은 localStorage의 별도 키에 둔다(실패해도 기본값 맨 위).
  - 확장 8의 악기 녹음은 mp3를 base64로 담은 일반 JS 파일(`js/data/instruments/…`)로 둔다(file://에서 fetch 없이 읽힘). 피아노는 페이지와 함께 읽고, 다른 악기는 고를 때 `<script>` 태그를 더해 읽는다. 브라우저 내장 Web Audio(decodeAudioData, AudioBufferSourceNode)로 재생하고 외부 라이브러리는 쓰지 않는다. 녹음 변환은 개발용 Python 스크립트(`tools/`)와 ffmpeg로 하고, 원본 WAV는 저장소에 넣지 않는다. 악기 설정은 `ltw.settings.v1`에 더한다.
- 대상 브라우저: 데스크톱 Chrome·Edge 최신 버전, 모바일 Chrome

## 9. 결정하거나 조사해야 할 것 (열린 질문) — 결정 완료

멜로디 모드
- 음역 범위: 자연음 + 반음(#, ♭) 포함, 1옥타브(C4~C5), 높은음자리표
- 조성: 다장조 고정 (초급 청음의 보편적 방식)
- 멜로디 길이: 3~8음 (쉬움 3~4 / 중간 5~6 / 어려움 7~8)
- 채점 방식: 음별 정답/오답 표시 (부분 점수), 이명동음 인정
- 피드백: 채점 후 정답 공개, 음 개수 미리 표시, 마지막 음 지우기 제공

화성 모드
- 문제 방식: 화음 구성음 받아적기 (화음 종류 맞히기·화성 진행 받아적기가 아님)
- 재생 방식: 동시에 울림 + "펼쳐 듣기" 버튼
- 화면 구성: 상단 모드 탭 [멜로디 | 화성], 파일 하나(index.html)
- 음역 범위: C4~G5 (오선 바로 위 칸 솔까지라 위쪽 덧줄 없음)
- 난이도: 쉬움 장·단 기본 위치 / 중간 장·단·감·증 기본 위치 / 어려움 + 자리바꿈 (청음 교육의 보편적 순서 기준)
- 입력 수정: 같은 자리 다시 누르면 지워짐 + 지우기 버튼
- 채점: 순서 무관 음높이 비교, 옥타브 일치 필요, 이명동음 인정
- 결과 표시: 구성음별 정답 + 빠뜨린 음 + 정답 화음 오선과 이름

7화음 (확장 2)
- 넣는 방식: 화성 모드 안의 [3화음 | 7화음] 선택, 7화음 전용 쉬움/중간/어려움 (새 모드 탭 아님)
- 종류: 속7·장7·단7·반감7·감7
- 난이도: 쉬움 속7·장7 기본 위치 / 중간 다섯 종류 기본 위치 / 어려움 + 자리바꿈(첫째~셋째)
- 음역: 3화음과 같은 C4~G5 (덧줄 추가 없음)
- 채점·결과: 3화음과 같은 규칙, 구성음 4개

리듬 모드 (확장 3)
- 화면 구성: 상단 모드 탭 [멜로디 | 화성 | 리듬]
- 입력 방식: 음표 버튼 (오선 클릭 아님, 그림 + 작은 글자), 8분음표는 하나씩, 마디 자동 나눔, 남은 박에 안 들어가는 버튼 비활성, 마우스 미리보기 없음
- 재생: 한 높이의 음을 음표 길이만큼, 마디 첫 박 강세, ♩= 80. 카운트인은 쉬움·중간 1마디(첫 박 높은 소리), 어려움 강세 없는 4번
- 음표: 온·점2분·2분·점4분·4분·8분음표, 4분쉼표
- 박자: 2/4·3/4·4/4. 쉬움·중간은 주어짐, 어려움은 사용자가 고름 (박자표 없는 한 마디에서 시작, 마디가 차면 추가, 최대 4마디, 박자표 바꾸면 입력 지움)
- 난이도: 쉬움 2마디 온·2분·4분 / 중간 2마디 + 8분·점2분·4분쉼표 / 어려움 3~4마디 + 점4분 + 박자표 고르기
- 채점: 마디별 정답/오답 (부분 점수). 어려움은 박자표가 틀리면 전부 오답
- 결과 표시: 마디별 정답 + (어려움) 박자표 정답/오답 + 정답 리듬 보표
- 휴대폰 화면: 듣기 버튼 빈자리 유지, 어려움 보표는 처음부터 두 줄 높이 (받아 적기 영역과 결과 영역 위치 고정)

내 악보 (확장 4)
- 입력 방식 로드맵: 직접 입력(확장 4) → MusicXML 불러오기 → 악보 인식(OCR)·곡 검색
- 화면 구성: 상단 모드 탭 [멜로디 | 화성 | 리듬 | 내 악보], "난이도" 자리에 "악보" 패널(악보 선택 + 구간 칩), 편집은 같은 탭 안의 편집 화면
- 악보 범위: 단선율, 다장조, 높은음자리표, C4~G5, 2/4·3/4·4/4, 리듬 모드의 음표 7종, 최대 12마디 (예시 "반짝반짝 작은 별" 4/4 12마디가 다 들어가도록), 못갖춘마디 없음(앞을 쉼표로 채움)
- 편집: 길이 버튼으로 길이 고르기 + 오선 입력판으로 높이 넣기, 마디 자동 나눔, 남은 박 규칙, 악보 보기로 바로 확인. 편집 화면은 듣기·받아 적기·결과 자리를 대신하고, 편집 중 탭을 바꾸면 취소
- 임시표: 음마다 실제 음높이로 저장, 악보 보기는 표준 표기(마디 안 첫 변화음에만 ♯/♭, 되돌아가면 ♮)
- 연습: 음높이만 받아 적기, 2마디씩 구간 출제(음 8개 초과면 1마디), 리듬대로 재생(첫 박 강세 없음), 다음 문제 = 다음 구간
- 저장: 브라우저(localStorage, 접두어·버전 붙인 키), 불러올 때 악보별 검증, 예시 악보 1개(목록이 없을 때만), 삭제는 두 번 눌러 확정

- 심화에서 난이도 선택 → 카운트인(겹박자는 점4분음표 박) → 리듬 재생 → (어려움: 박자표 6개 중 고르기) → 길이·점·쉼표·셋잇단·붙임줄로 입력 → 제출 → 마디별 소리 기준 채점과 정답 리듬 공개 → 다음 문제까지, 한 사이클을 막힘 없이 마칠 수 있다
- 심화의 난이도별 리듬이 5개 이상 있고, 16분음표·점8분음표·8분쉼표·셋잇단음표·붙임줄·6/8·9/8·12/8이 모두 출제된다
- 같은 소리를 다르게 적은 답(예: 4분음표 ↔ 8분⌒8분)이 정답으로 채점되고, 셋잇단·붙임줄·겹박자가 정확한 길이로 재생된다
- 대상 브라우저와 file:// 환경에서 리듬 심화도 레이아웃이 깨지지 않고(320px 포함) 콘솔 에러 없이 동작하며, 모드·종류를 바꿔도 받아 적기 영역 위치가 움직이지 않는다

확장 10 (악보 자동 계이름 표시)
- 모드 탭으로 네 모드를 오가도 각 모드가 정상 동작하고, 연습·편집기·불러오기 등 기존 기능이 그대로 유지된다
- 예시 악보와 불러온 악보를 [보기]로 열면 악보 전체의 음표 아래에 계이름이 붙고(이동도·고정도, 조바뀜, 단조 라, 임시표, 붙임줄·쉼표 제외, 화음 세로, 꾸밈음 작게), ⚙에서 방식을 바꾸면 바로 바뀐다
- [인쇄]로 제목과 계이름 달린 악보만 쪽 너비에 맞게 인쇄(PDF 저장)할 수 있다
- 받아 적기 결과의 정답 구간 악보에 계이름이 붙고 정답/오답 색이 보이며, 연습 중에는 계이름이 보이지 않는다
- 대상 브라우저와 file:// 환경에서 보기 화면도 레이아웃이 깨지지 않고(320px 포함) 콘솔 에러 없이 동작하며, 모드를 바꿔도 받아 적기 영역 위치가 움직이지 않는다

## 11. 다음 확장 로드맵 (메모)

확장 5(원곡 악보 형식)로 원곡을 바꾸지 않고 담을 그릇을 만들고, 확장 6(MusicXML 불러오기, 4-G)으로 파일을 그대로 옮겨 담는다. 그다음은 악보를 넣고 고치는 방법을 넓힌다. 어떤 연습을 줄 수 있는지는 입력 방법이 아니라 **얻은 데이터**(음높이·길이·박자·조성·화음)에 달려 있다. 그래서 어느 방법이든 결과를 확장 4의 악보 형식으로 바꾸면 같은 연습을 쓰고, 확장 4의 편집기는 불러온 악보를 고치는 도구로 다시 쓴다.

- 다음 — 악보 인식(OCR) / 곡 검색 (확장 10 다음, 2026-11-01 사용자 결정 순서) (인식 결과는 확장 7의 편집기로 고친다)
  - 연습 종류: 결과가 MusicXML이면 MusicXML과 같다.
  - 한계 1, 정확도: 인식 오류가 생기므로 편집기로 고치는 단계가 꼭 필요하다.
  - 한계 2, 곡 출처·저작권: 저작권이 있는 곡(대중가요 대부분)은 악보를 제공하기 어렵다. 공개 악보 모음(공유저작물 위주)에 기대게 된다.
  - 한계 3, 기술 조건: 인식 엔진과 검색은 서버나 네트워크가 필요할 수 있어, "서버 없이 file://로 동작" 원칙(7번)을 다시 정해야 한다.
- MusicXML의 화음·여러 성부 정보는 이후 화성·선율 연습으로 넓힐 바탕이 된다. 리듬 심화(확장 9)의 입력·채점은 멜로디와 리듬을 합친 선율 청음(5번)의 바탕이 된다.
